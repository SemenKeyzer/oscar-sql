## 2. Правила, которые соблюдались

- Qt 6 / C++17, qmake. Предупреждения — ошибки (кроме deprecated). Проверять сборку GCC и
  синтаксис Clang, а для изменённых файлов — ещё и против заголовков Qt 6.10 и 6.11. CI
  на GitHub собирает с Qt 6.4 и 6.10.
- Тесты: QTest, все классы в одном бинарнике (`DECLARE_TEST`). Новые тестовые файлы
  добавлять в `oscar/oscar.pro` (раздел `test`).
- Коммиты: сообщение по-английски, в стиле существующих (что и зачем), с трейлерами
  `Co-Authored-By:` и `Claude-Session:`. Имена моделей в коммиты не писать.
- Комментарии в коде — по плотности и стилю как в окружающем коде.

### Сборка и тесты

```bash
# приложение
mkdir -p ../build && cd ../build && qmake6 ../oscar-sql/oscar/oscar.pro && make -j8
# тесты
mkdir -p ../build-test && cd ../build-test
qmake6 ../oscar-sql/oscar/oscar.pro CONFIG+=test && make -j8
QT_QPA_PLATFORM=offscreen ASAN_OPTIONS=detect_leaks=0 ./test
```

На момент передачи: 349 тестов проходят, 3 пропущены (нет тестовых данных
`testdata/profile/tpo-25apr25`, так было и раньше).

Проверка против Qt 6.10/6.11 делалась так: пакеты `qt6-main` и `qt6-serialport` с
conda-forge распаковывались в каталог, затем `clang -fsyntax-only` с include-путями оттуда.
В этих пакетах нет QtBluetooth, поэтому `tests/contecbleimporttests.cpp` там не проверяется.

### Перевод (русский)

```bash
/usr/lib/qt6/bin/lupdate oscar/oscar.pro -ts Translations/Russkiy.ru.ts
python3 docs/superpowers/tools/validate_ts.py Translations/Russkiy.ru.ts   # должно быть TOTAL 0
grep -c 'type="unfinished"' Translations/Russkiy.ru.ts                      # сейчас 0
```

- Валидатор проверяет, что в переводе сохранены плейсхолдеры, HTML-теги, ссылки,
  `&`-ускорители и переносы строк.
- Термины: сеанс (session), аппарат (CPAP machine), устройство (прочее «железо»),
  Дневник (Journal), разгон (Ramp), вкладки «День» / «Сводка» / «Статистика»,
  отправка (upload). Аббревиатуры (AHI, RERA, OH, CH, ODI, SpO2) — латиницей.
- Строки из свободных функций нужно писать через `QCoreApplication::translate("Контекст", "...")`,
  иначе lupdate их не видит. В глобальных переменных `tr()` не вызывать: глобальные переменные
  инициализируются до установки переводчика.
