# RS01 Clock over USB HID (stage 3) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

Fork-only, not for MR.

**Goal:** OSCAR sets the Contec RS01's clock from the computer's local time over USB HID: once when the RS01 page lists the device's own disk, and on «Set clock».

**Architecture:** a pure command/reply module (`rs01_clock`), a transport over vendored hidapi (`rs01_hid`, macOS + Windows, stub elsewhere), and the RS01 page's clock line and button.

**Tech Stack:** C++17, Qt 6, qmake; hidapi 0.15.0 (C); QtTest via `../tools/runtests.sh`.

**Spec:** `docs/superpowers/specs/2026-10-21-rs01-clock-design.md`

## Global Constraints

- Only `81 01` (identify) and `83 YY MM DD hh mm ss 00 00 CK` (set clock) are ever sent; never `84`, `8B` or protocol B.
- Writes 65 bytes (report ID 0x00 + 64 zero-padded), replies read with a 1 s timeout each.
- `CK = ((cmd & 0x7F) + Σ params) & 0x7F`; YY = year − 2000; local time; years outside 2000–2127 refused.
- VID 0x28E9, PID 0x01F3. Identify reply starts `F1` and contains `RS01`; clock reply is `F3 00 73`.
- The device's disk stays read-only; nothing in this stage writes to it.
- hidapi in `oscar/SleepLib/thirdparty/hidapi/` (hidapi.h, mac/hid.c + hidapi_darwin.h, windows/hid.c + its headers and hidapi_descriptor_reconstruct.{c,h}, LICENSE*.txt); macOS links `-framework IOKit -framework CoreFoundation`; Windows needs no extra libs (hidapi loads hid.dll/cfgmgr32 itself); Linux: stub, button hidden.
- No automated test talks to a device.

## Review Focus

1. No RS01 plugged in (only the disk copy in a folder) — no clock attempt, no error line; button says device not found when pressed.
2. Device plugged in but another HID device with the same VID/PID absent / the reply short or late — error text, import still works.
3. The reply comes with report ID or padding differences (64 bytes, maybe leading 0x00) — accepted when the payload matches.
4. Windows build compiles the vendored C (MSVC, WINVER=0x0501 define in oscar.pro) — note: verified only by the next Windows CI build.
5. Linux build — stub compiles, button hidden.

### Task 1: Commands and replies
**Files:** create `oscar/SleepLib/loader_plugins/rs01_clock.{h,cpp}`, `oscar/tests/rs01clocktests.{h,cpp}`; `oscar/oscar.pro`.
**Produces:** `quint8 rs01Checksum(const QByteArray &cmdAndParams)`; `QByteArray rs01IdentifyCommand()` (64 bytes); `QByteArray rs01ClockCommand(const QDateTime &local)` (64 bytes, empty if the year is out of range); `bool rs01IsIdentifyReply(const QByteArray &)`; `bool rs01IsClockReply(const QByteArray &)` (both skip one leading 0x00 report byte if present).
- [ ] Tests: `testChecksum` (`F3 00` → 0x73; `83 1A 0A 15 16 0F 03 00 00` → (3+26+10+21+22+15+3)&0x7F = 100 = 0x64); `testClockCommand` (2026-10-21 22:15:03 → `83 1A 0A 15 16 0F 03 00 00 64` + zeros, size 64); `testClockYearRange` (1999, 2128 → empty; 2127 ok); `testIdentifyCommand` (`81 01`: no params, so the checksum is (0x81&0x7F) = 01 — the notes' «81 01» is command + checksum; likewise `8B 04 00 0F`); `testReplies` (replies carry the same checksum: `F1 "RS01    " 77` ok (0x71+Σ"RS01    " = 0x1F7 → 0x77), wrong checksum refused, `82…` refused, `F3 00 73` ok, `F3 01 74` refused, with and without leading 0x00).
- [ ] Red, implement, green, suite, commit "RS01: clock commands and replies".
