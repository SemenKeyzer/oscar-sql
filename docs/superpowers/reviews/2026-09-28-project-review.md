## Как проводилось
- Шесть независимых проходов по областям: база данных и резервные копии; сеть, обмен
  и приватность; ядро `SleepLib`; загрузчики устройств; GUI; сборка, тесты и инструменты.
- Каждый проход читал код вместе с вызывающими и вызываемыми местами; спекулятивное
  отбрасывалось.
- Главные находки каждой области перепроверены вручную — они помечены **✔**. Остальные —
  по чтению кода агентом (**◦**), их стоит подтвердить при исправлении.
- Одна находка **опровергнута** (см. в конце).
- Сборка тестов (`qmake6 CONFIG+=test`, Qt 6.4.2, GCC 13) после коммита `e30f3dc` проходит;
  все наборы зелёные, кроме `EventsTabTests` — ему нужны данные `./testdata`, которых нет
  в репозитории.

## Опровергнуто
- «Data → Rebuild Oximetry Index обнуляет статистику и не сохраняет события» — неверно:
  `Machine::Save()` ставит изменённые сессии в очередь `SaveTask`, а `SaveTask::run()`
  вызывает `UpdateSummaries()` и `Store()` (`machine.cpp:78-84`).

## Что это значит для функции анализа
Спецификация анализа (`specs/2026-09-28-sleep-analysis-design.md`) опирается на
скорректированное время. Находки ядра про поправки времени (`calcAHIGraph`, `AddSession`,
`Day::total_time`, отсутствие обновления сводок после поправки) стоит исправить **до** или
**вместе** с этапом 2 анализа, иначе сравнение с аппаратом унаследует эти сдвиги.
Находка о `noteReportedChannels` подтверждает решение исключать вычисленные каналы из
«возможностей устройства».
