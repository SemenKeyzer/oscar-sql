## 1. Цель и контекст

### Проблема
OSCAR показывает только события, которые отметил сам аппарат (OA, CA, H, RERA, FL…).
Проверить их независимо нельзя: алгоритмы аппаратов закрыты, различаются между
производителями (ResMed и Löwenstein Prisma считают по-разному) и не учитывают оксиметр.
Анализ SpO₂ и пульса в OSCAR примитивен и частично сломан (см. ниже).

### Что уже есть (переиспользуем / чиним)
- **User Flags UF1/UF2** (`SleepLib/calcs.cpp:738`, `FlowParser::flagUserEvents`) —
  единственное собственное обнаружение событий: промежуток между «хорошими» вдохами
  длиннее N с при потоке ниже X % от одного общего для сессии пика (60-й перцентиль).
  Нет скользящей базовой линии, гипопноэ, классификации, ограничения потока.
- **`FlowParser`** (`calcs.cpp:201-736`) — сегментация дыханий по пересечению нуля без
  гистерезиса и без коррекции смещения; отвергнутые циклы сливаются с соседними,
  буфер ограничен ~6 ч при 100 Гц. Для точного поддыхательного анализа не годится —
  пишем свою сегментацию, `FlowParser` не трогаем.
- **SpO2 Drop** (`calcs.cpp:1500`) — это не ODI: базовая линия фиксированная
  (90-й перцентиль первого часа), считается время ниже порога. **Баг:** `min` не
  обновляется, глубина события всегда сохраняется как 0 (`calcs.cpp:1627-1644`).
- **Pulse Change** (`calcs.cpp:1421`) — сохраняет разницу с последним значением окна,
  а не максимальную (`tmp` вместо `max`, `calcs.cpp:1478`).
- **Поправки времени устройств** (`device_time_corrections`, `Machine::correctionMs`,
  `Session::correctionMs`) применяются при чтении, сырые времена событий не меняются.
  Выравнивание оксиметра в окне «День» (`TimeAlignSession`, `TimeAlignBar`) — готово.
- Общие механизмы, которые подхватывают новые каналы сами: график флагов,
  дерево событий, вкладка поиска, наложения флагов на графики (`gLineChart.cpp:219-249`),
  `session_channels`.

### Цель
Добавить в OSCAR **собственный анализ ночи** («второе мнение»), независимый от
алгоритмов аппарата:
1. **Поток CPAP:** апноэ (обструктивные / центральные / неклассифицированные),
   гипопноэ (с подтверждением десатурацией, если есть оксиметр), ограничение потока
   по форме вдоха, RERA-подобные эпизоды, периодическое дыхание.
2. **Оксиметрия:** ODI 3 % / 4 % со скользящей базовой линией, время ниже порогов SpO₂, проблемные зоны, надир,
   гипоксическая нагрузка, циклические десатурации; пульс — подъёмы пульса (маркер
   вегетативных пробуждений), реакция пульса на события (ΔHR), бради/тахикардия.
3. **Сравнение с аппаратом:** совпавшие события, «только аппарат», «только анализ»,
   расхождения типа; AHI аппарата рядом с AHI анализа.
4. **Показ везде понемногу:** флаги и графики в «Дне», панель сравнения, тренды в
   «Обзоре», строки в «Статистике», таблица в SQL.

### Критерии успеха
1. Для любой ночи с потоком CPAP ≥ 4 Гц окно «День» показывает флаги анализа и таблицу
   «Аппарат | Анализ»; для ночей с оксиметрией (в том числе **без CPAP**) — ODI, время ниже
   порогов SpO₂, проблемные зоны, надир, показатели пульса.
2. Подтверждение гипопноэ десатурацией учитывает поправки времени оксиметра; после
   выравнивания оксиметра в «Дне» результаты анализа обновляются сразу, без перезапуска.
3. «Обзор» и «Статистика» показывают тренды показателей анализа за годы без заметного
   замедления (чтение из таблицы `analysis_daily`, без загрузки волн).
4. Анализ **никогда** не меняет данные устройства, AHI/статистику аппарата и не влияет на
   «возможности устройства» (capability gating OH/CH).
5. Одинаковые входные данные и настройки дают одинаковый результат; при смене настроек
   предлагается пересчёт.
6. Этап 1 на одну ночь (ResMed 25 Гц, 8 ч) — ≤ 0,5 с на обычном ноутбуке; импорт
   замедляется не более чем на 20 %.
7. Юнит-тесты на синтетических сигналах покрывают каждый детектор; сборка без
   предупреждений; все существующие тесты проходят.
8. Ориентир настройки (не жёсткий критерий): на данных пользователя (ResMed + Prisma,
   ≥ 30 ночей) ≥ 70 % апноэ аппарата находят пару в анализе.

### Решения пользователя (из обсуждения)
- Данные для отладки: **Löwenstein Prisma** и **ResMed AirSense**; оксиметр — Contec CMS50FW.
- Объём: **всё сразу** — оксиметрия, второе мнение по потоку и сравнение в одной
  спецификации и одном плане (реализация по этапам внутри ветки).
- Показ: **везде понемногу** — флаги на графиках «Дня», панель «Анализ» с таблицей
  «аппарат vs анализ», тренды в «Обзоре», строки в «Статистике».
- Правило гипопноэ: **селектор с подробным описанием разницы** между правилами прямо
  в настройках (§5.4); по умолчанию Auto.
- Оксиметрия **самостоятельна**: по умолчанию анализируется вся запись оксиметра,
  ограничение временем CPAP — только опция. Ночь только с оксиметром (без CPAP) — полноценный
  сценарий: показать **проблемные зоны** и **сколько времени SpO₂ была ниже заданных
  порогов** (§3.2.7, §3.2.8).
- Классификация апноэ: включена по умолчанию (экспериментально).
- Отправка в upstream **отложена** до прогона всех тестов на реальных данных.

### Ограничение ответственности
Анализ — инструмент самопроверки, не диагноз. В панели «Анализ» и в справке постоянно
видна строка: *«Experimental analysis for self-review. It is not a medical diagnosis;
discuss therapy changes with your clinician.»* Названия каналов помечаются «(analysis)».

## 2. Общие правила

- **Время.** Все времена — мс от эпохи, как в OSCAR. Этап 1 работает в сыром времени
  устройства. Этап 2 (сведение устройств за день) переводит всё в скорректированное
  время: `t + session->correctionMs()`.
- **Соглашение для наших событий** — как в OSCAR: метка времени = **конец** события,
  `data` = длительность в секундах, `data2` — доп. величина (глубина, % снижения…).
  Отрисовка спанов идёт назад от метки (`gLineOverlay.cpp:131`).
- **Единицы потока не важны:** все пороги потока относительные (к базовой линии или к
  медиане ночи). Prisma берёт единицы из заголовка EDF, ResMed — л/мин.
- **Знак потока:** вдох положительный (как в `FlowParser`). Проверяется вручную на
  данных ResMed и Prisma (§7.2).
- **Время анализа потока** = время с валидным потоком минус «неоцениваемые» участки
  (§3.3.8). Индексы анализа считаются на это время, AHI аппарата — на его время
  использования; знаменатели показываются рядом.
- **Время анализа оксиметрии** = все секунды с валидной SpO₂ (вся запись оксиметра,
  с CPAP или без). Опция «Limit oximetry metrics to CPAP usage time» (по умолчанию
  **выключена**) ограничивает показатели пересечением со (скорректированным) временем
  сессий CPAP, если CPAP в эту ночь был. Связь десатураций с дыхательными событиями
  (§3.4.3–3.4.5) считается только там, где есть CPAP, независимо от опции.
- **Выключенные сессии** (`enabled = false`) в анализ не входят.
- **Apple Health** (редкие точечные замеры) в анализ оксиметрии не входит — как в
  `calcSPO2Drop`.

## 3. Алгоритмы

Все детекторы — чистые функции над векторами (без `Session`/`Profile`), чтобы их можно
было проверять на синтетике. Параметры по умолчанию — §3.5.

### 3.1 Подготовка оксиметрии
1. Источник: каналы `OXI_SPO2`, `OXI_Pulse` любой сессии (оксиметр или ResMed с
   адаптером). Хранение бывает двух видов: «по изменению» (CMS50, Contec BLE, ResMed —
   точка только при смене значения, 0 = разрыв, новый список после разрыва) и волна
   с фиксированным шагом (Viatom, 1–4 с). Время отсчёта — `EventList::time(i)`.
2. Сетка 1 Гц на интервале каждого списка: значение удерживается до следующей точки
   внутри списка; между списками — разрыв.
3. Недостоверно: SpO₂ вне [50, 100], пульс вне [30, 220], нули.
4. Фильтр выбросов: медиана по окну 5 с (SpO₂) и 5 с (пульс). Скачок SpO₂ ≥ 10 п.п.
   за ≤ 2 с с возвратом за ≤ 5 с — артефакт, отсчёты помечаются недостоверными.
5. Разрыв ≥ 10 с делит сигнал на сегменты; сегменты < 60 с отбрасываются.
6. Если в ночь несколько источников SpO₂, берётся источник с наибольшим валидным
   временем; в панели указывается, какой именно.

### 3.2 Оксиметрия (этап 1, на сессию)

**3.2.1 Десатурации (пик — надир).** Конечный автомат по сглаженной SpO₂ `s(t)`:
- `ref(t)` = максимум `s` на окне `[max(t − 120 с, T_end_prev), t]`, где `T_end_prev` —
  конец предыдущей десатурации (после события эталон берётся только из новых данных,
  поэтому каждая «ступенька» в серии меряется от своего пика).
- Вход в событие: `s(t) ≤ ref(t) − 3`. Пик `Pv = ref`, `Pt` — последний момент, где
  `s = Pv`. Начало `St` — первый отсчёт после `Pt`, где `s ≤ Pv − 1`.
- В событии копится надир `Nv, Nt`. Конец `Et` — первый отсчёт после `Nt`, где
  `s ≥ Pv − 1` или `s ≥ Nv + ⅔·(Pv − Nv)` (частичное восстановление — начало следующего
  события в серии).
- Отбрасывается: `Et − St < 10 с`; спад `Pt → Nt` дольше 120 с (медленный дрейф —
  учитывается только в T90). Событие длиннее 180 с обрезается на 180 с.
- Результат: `start, nadirTime, end, depth = Pv − Nv, area = Σ(Pv − s)·Δt` (%·с).
- ODI3 — события с `depth ≥ 3`; **ODI4 — подмножество той же серии с `depth ≥ 4`**
  (отдельного прохода с 4 % нет; это осознанное упрощение, документируется).

**3.2.2 Показатели SpO₂:** среднее, медиана, надир (минимум после фильтра), время ниже
порогов (§3.2.7), средняя глубина и длительность десатураций, индекс площади десатураций
`Σarea / 60 / часы` (%·мин/ч).

**3.2.3 Циклические десатурации:** ≥ 3 подряд десатураций (`depth ≥ 3`) с интервалом
надир–надир 20–120 с — эпизод (SPAN от начала первой до конца последней). Показатели:
число эпизодов, суммарное время.

**3.2.4 Подъёмы пульса.** По сглаженному пульсу `p(t)`:
- базовая линия `b(t)` = медиана `p` на `[t − 30 с, t − 5 с]` (нужно ≥ 15 валидных отсчётов);
- начало `t0`: `p − b ≥ ΔR/2`, и в течение ≤ 10 с `p` достигает `b(t0) + ΔR`
  (`ΔR` = 6 уд/мин по умолчанию);
- над порогом `b + ΔR` не менее 3 с; конец — `p ≤ b(t0) + ΔR/2` или 60 с;
  следующее событие не раньше чем через 5 с после конца;
- результат: время конца, длительность, амплитуда `max p − b(t0)`.

**3.2.5 Бради- и тахикардия:** `p < 40` или `p > 120` уд/мин непрерывно ≥ 30 с — SPAN.
Пороги настраиваются.

**3.2.6 Показатели пульса:** среднее, минимум, максимум, СКО, индекс подъёмов пульса (/ч).

**3.2.7 Время в диапазонах SpO₂ и пульса.**
- За ночь копится **гистограмма**: секунды валидной SpO₂ по каждому целому проценту
  50…100 и секунды пульса по каждому уд/мин 30…220. Гистограммы хранятся (§4.3), поэтому
  любые пороги считаются при чтении, без пересчёта анализа.
- Пороги SpO₂ — настраиваемый список до 6 значений, по умолчанию **94, 90, 88, 85, 80 %**.
  Показывается «время ниже порога» (мин и % времени анализа) и таблица диапазонов:
  `≥ 95`, `90–94`, `88–89`, `85–87`, `80–84`, `< 80` (границы следуют списку порогов).
- Пульс: время ниже нижнего порога, в норме, выше верхнего (пороги бради/тахи §3.2.5).
- T90 — стандартное имя для «время ниже 90 %» в отчётах и SQL; отдельной колонки нет.

**3.2.8 Проблемные зоны** — участки ночи, на которые стоит посмотреть; главный вывод для
ночи только с оксиметром.
- Скользящее окно 5 мин с шагом 30 с. Окно «проблемное», если выполнено хотя бы одно:
  - ≥ 3 десатураций (`depth ≥ 3`) с надиром в окне (≈ ODI ≥ 36/ч локально);
  - ≥ 60 с ниже «низкого» порога (по умолчанию 90 %);
  - ≥ 30 с ниже «критического» порога (по умолчанию 85 %).
- Соседние и перекрывающиеся проблемные окна сливаются в зону; зоны короче 2 мин
  отбрасываются; зоны ближе 2 мин друг к другу объединяются.
- Тяжесть зоны: **2 (выраженная)**, если минимум SpO₂ в зоне < критического порога или
  в зоне ≥ 30 с ниже него; иначе **1 (умеренная)**.
- На зону: начало, длительность, минимум SpO₂, число десатураций, секунды ниже низкого
  и критического порогов, средний пульс и число подъёмов пульса.
- Канал `AN_OxiProblemZone` (SPAN, `data2` = тяжесть) — рисуется на графике SpO₂ и в
  флагах анализа; зоны перечислены в вкладке «Analysis» с переходом по щелчку.

### 3.3 Поток CPAP (этап 1, на сессию)

**3.3.1 Подготовка.**
- Источник — `CPAP_FlowRate` (несколько списков на сессию = несколько кусков с разрывами;
  ResMed пишет отдельный кусок на каждый BRP-файл).
- `fs = 1000 / rate_ms`. `fs < 4 Гц` — анализ потока выключен (примечание в панели).
  `4 ≤ fs < 10 Гц` — нет оценки формы вдоха (FL) и кардиогенных осцилляций.
  `fs > 25 Гц` — прореживание усреднением до 25 Гц (Prisma: частота берётся из заголовка
  `.wmedf`, в репозитории не задокументирована — проверить на данных).
- Смещение: вычитается скользящее среднее по окну 20 с (дрейф компенсации утечки).
- Сглаживание для сегментации: скользящее среднее 200 мс.

**3.3.2 Сегментация дыханий.** Пересечения нуля с гистерезисом `h = 0,1 · P90(|x|)` на
последних 60 с. Дыхание = от восходящего пересечения до следующего восходящего; вдох —
до нисходящего. Отбрасываются дыхания короче 1 с и длиннее 15 с (длинные промежутки —
«нет дыхания», не сливаются с соседями). На дыхание: `start, Ti, Te, PIF, PEF,
Vi = ∫x⁺dt`, амплитуда `a = PIF − PEF`.

**3.3.3 Огибающая и базовая линия** (частота 1 Гц):
- `E(t)` = размах (`max − min`) сглаженного потока в окне длиной `L = 1,2 ×` медианный
  период дыхания за последние 120 с (ограничено 3–10 с). Апноэ дают малый `E` без
  зависимости от сегментации.
- `B(t)` = 70-й перцентиль `E` на `[t − 120 с, t − 1 с]` без неоцениваемых участков.
- `E_night` = медиана `E` за валидное время сессии; `B < 0,2·E_night` — «слабый сигнал»
  (неоцениваемо).

**3.3.4 Кандидаты событий** (автомат на 1 Гц):
- Вход: `E(t) ≤ 0,7·B(t)`; базовая линия фиксируется: `B_ref = B(t_вход)`.
- Событие длится, пока `E ≤ 0,7·B_ref`; допускаются провалы вверх до 2 с.
- Конец — первая секунда, после которой `E > 0,7·B_ref` не менее 3 с подряд.
- `D < 10 с` — отбрасывается; `D > 120 с` — не событие, а неоцениваемый участок.
- **Апноэ**, если внутри есть ≥ 10 с подряд с `E ≤ 0,1·B_ref` (снижение ≥ 90 %, AASM);
  длительность апноэ = длительность кандидата.
- Иначе — **кандидат гипопноэ** `AN_FlowReduction`, `data2` = медиана снижения
  `1 − E/B_ref` за событие, в %.
- Смешанные апноэ отдельно не выделяются (вне рамок).

**3.3.5 Ограничение потока (FL) по форме вдоха** (только `fs ≥ 10 Гц`, `Ti ≥ 0,6 с`):
- Вдох нормируется: время → `τ ∈ [0, 1]`, поток → `u = x / PIF`, 32 точки.
- Плато: `F` = доля `τ ∈ [0,2; 0,8]` с `u ≥ 0,85`; у синусоиды ≈ 0,6, у плоской вершины
  ≈ 1. `F' = clamp((F − 0,6)/0,35)`.
- Провал в середине («M-форма»): локальный минимум при `τ ∈ [0,25; 0,75]` со значением
  ≤ 0,8 между двумя максимумами ≥ 0,9. `D' = clamp((0,95 − min)/0,25)`.
- Ранний пик и полка («кресло»): пик при `τ ≤ 0,3`, среднее `u` на `[0,4; 0,8]` в
  `[0,5; 0,85]` и малый наклон. `C'` ∈ [0, 1].
- `FL = max(F', D', C')` ∈ [0, 1]; дыхание «ограничено», если `FL ≥ 0,5`.
- Каналы: `AN_FLScore` (значение на каждое дыхание, график 0–1 как ResMed FLG);
  `AN_FlowLimitation` (SPAN) — ≥ 3 подряд ограниченных дыханий (или ≥ 10 с), вне апноэ
  и гипопноэ.
- Показатели: % времени в FL, средний FL, P95 FL.

**3.3.6 Классификация апноэ** (эвристика, настройка «Classify apneas (experimental)»,
по умолчанию включена). Сумма свидетельств `S`:
- Кардиогенные осцилляции (только `fs ≥ 10 Гц`): внутри апноэ без первых и последних
  2 с — окна 4 с с шагом 1 с; пик спектра в 0,7–2,5 Гц (или у частоты пульса ± 0,15 Гц,
  если в той же сессии есть `OXI_Pulse`) мощнее среднего по 3–6 Гц в ≥ 4 раза и с
  амплитудой ≥ 2 % `B_ref`. Есть в ≥ 50 % окон → **−1** (дыхательные пути открыты).
- ≥ 2 из 3 дыханий перед событием ограничены (`FL ≥ 0,5`) → **+0,5**.
- Резкое восстановление: первое дыхание после события `a ≥ 1,2·B_ref` и ≥ 2× последнего
  дыхания до события → **+0,5**.
- Убывание («декрещендо»): 3 дыхания перед событием каждое ≤ 85 % предыдущего и
  `FL < 0,3` → **−0,5**.
- Событие внутри эпизода периодического дыхания → **−0,5**.
- Prisma `ObstructLevel` (0–100 %): среднее за событие ≥ 50 → **+1**, ≤ 20 → **−1**
  (пороги начальные, уточняются на данных).
- Итог: `S ≥ 0,75` → `AN_ObstructiveApnea`, `S ≤ −0,75` → `AN_CentralApnea`,
  иначе `AN_Apnea`.

**3.3.7 RERA-подобные эпизоды (по потоку).** ≥ 2 подряд дыханий общей длительностью
≥ 10 с с `FL ≥ 0,5` **или** с убывающей амплитудой, не входящих в апноэ/гипопноэ,
завершающихся дыханием с амплитудой ≥ 1,5 × средней по эпизоду → `AN_RERA`.

**3.3.8 Периодическое дыхание.** По `E(t)`: окна 600 с с шагом 60 с, автокорреляция
на лагах 30–100 с; окно периодично, если пик АКФ ≥ 0,5 и `(P90 − P10)/P90 ≥ 0,5`.
Соседние окна сливаются, эпизоды ≥ 10 мин → `AN_PeriodicBreathing` (SPAN,
`data2` = период, с).

**3.3.9 Неоцениваемые участки** → `AN_Unscoreable` (SPAN, по умолчанию скрыт):
разрывы потока, `CPAP_LargeLeak`, спаны артефактов и критической утечки Prisma,
«слабый сигнал» (§3.3.3), снижение потока дольше 120 с.

### 3.4 Сведение за день (этап 2)

Работает на скорректированном времени и только на событийных каналах и 1-Гц SpO₂/пульсе
(волна потока не нужна).

**3.4.1 Правило гипопноэ** (настройка, по умолчанию **Auto**):
- **AASM 3 %:** кандидат `[s, e]` подтверждён, если есть десатурация `depth ≥ 3` с надиром
  в `[s, e + 30 с]`;
- **CMS 4 %:** то же с `depth ≥ 4`;
- **Flow only:** снижение (`data2`) ≥ 50 %, без оксиметра — сопоставимо с алгоритмами
  аппаратов;
- **Auto:** AASM 3 % там, где на интервале `[s, e + 30 с]` есть валидная SpO₂; иначе
  Flow only. Для AASM/CMS кандидат без покрытия SpO₂ тоже оценивается по Flow only
  и учитывается как «не подтверждаемый» (в панели).
- Опция «Count pulse-rate rise as arousal» (по умолчанию выкл., не по AASM): подъём
  пульса в `[e − 5 с, e + 15 с]` тоже подтверждает гипопноэ.
- Независимо от выбранного правила этап 2 считает число гипопноэ **по всем трём**
  правилам (AASM 3 %, CMS 4 %, Flow only) — дёшево, кандидаты и десатурации уже есть.
  Панель «Анализ» показывает их строкой сравнения, чтобы разница между правилами была
  видна на своих данных; в `analysis_daily` хранятся все три счётчика.

**3.4.2 Классификация гипопноэ:** доля ограниченных дыханий (`AN_FLScore ≥ 0,5`) внутри
события ≥ 0,5 → `AN_ObstructiveHypopnea`; < 0,2 и событие внутри `AN_PeriodicBreathing` →
`AN_CentralHypopnea`; иначе `AN_Hypopnea`.

**3.4.3 Связь десатураций с событиями:** десатурация связана с дыхательным событием,
если её надир в `[начало события, конец + 30 с]`. Считается отдельно для событий анализа
и для событий аппарата. Несвязанные с событиями анализа десатурации — «необъяснённые»
(число и список в панели).

**3.4.4 Гипоксическая нагрузка (приближённо):** сумма площадей десатураций, связанных с
событиями анализа, делённая на часы анализа, в %·мин/ч. Площадь пересчитывается по 1-Гц
SpO₂ (в событии хранятся только длительность и глубина). Это упрощение метода Azarbarzin
(без ансамблевого окна); в интерфейсе — «Hypoxic burden (approx.)».

**3.4.5 Реакция пульса (ΔHR):** на событие `max p` на `[начало, конец + 20 с]` минус
среднее `p` на `[начало − 10 с, начало]`; среднее и число событий с валидным пульсом.
Также доля событий, за которыми в течение 15 с следует подъём пульса.

**3.4.6 Сравнение с аппаратом.**
- Группы: **апноэ** (аппарат: OA, CA, A/UA; анализ: aOA, aCA, aA), **гипопноэ** (H, OH, CH /
  aH, aOH, aCH), **RERA** (RERA / aRE).
- Интервал события аппарата зависит от соглашения загрузчика (`DeviceEventConvention`):
  по умолчанию «метка = конец» → `[t − d, t]`. **ResMed EVE хранит onset**
  (`resmed_loader.cpp:3800`), но OSCAR рисует его как конец; какое толкование верно,
  проверяется на данных (§7.2): этап 2 пишет в лог медиану смещения
  `t_устройства − t_конца_анализа` по совпавшим апноэ. Длительность −1 или 0 → 10 с.
- Сопоставление: интервалы расширяются на ±5 с; жадно по максимальному перекрытию,
  сначала внутри группы, затем между группами (это «расхождение типа»). Каждое событие
  участвует не более одного раза.
- Итог: совпало / только аппарат / только анализ по группам, матрица типов (включая
  OA/CA), согласие = `совпало / (аппарат + анализ − совпало)`.
- Дополнительно, только в панели (не хранится): FL — корреляция по минутам с ResMed
  `CPAP_FLG` или сопоставление со спанами FlowLimit Prisma; периодическое дыхание —
  перекрытие с CSR/PB аппарата.

**3.4.7 Подсказка о сдвиге часов оксиметра.** Если за ночь ≥ 10 десатураций и ≥ 10
дыхательных событий: для лага `L ∈ [−20 мин, +20 мин]` с шагом 5 с считаем десатурации
с `надир + L ∈ [конец события, конец + 40 с]`. Если лучший `L*` даёт ≥ 1,5× совпадений
от `L = 0`, не меньше 8 совпадений и `|L*| ≥ 30 с` — подсказка «Oximeter data may be
offset by about ±HH:MM:SS» со ссылкой **Align oximeter…**, открывающей режим выравнивания
(`Daily`, `TimeAlignBar`). Автоматически сдвиг не применяется.

### 4.3 Хранение
- **Этап 1** — обычные `EventList` в сессии → `event_lists`/`event_data` (без изменения
  схемы). Штамп в `session_settings` (канал `AN_Stamp`, `json_value`):
  `{"flow":{"v":1,"p":"<хеш>"},"oxi":{"v":1,"p":"<хеш>"}}`.
- **Этап 2** — каналы `AN_*Hypopnea` в сессии CPAP; сохраняются **точечно**, без
  перезаписи волн (см. ниже).
- **Точечная запись каналов:** `Session::StoreChannelEvents(const QList<ChannelID>&)` —
  удаляет и вставляет `event_lists` только этих каналов и обновляет их строки
  `session_channels`. Полная `StoreEventsToDatabase` удаляет все списки сессии и пишет
  заново, в том числе волны — для пересчёта анализа это слишком дорого.
- **Частичная загрузка:** `Session::LoadEventsFromDatabase(const QSet<ChannelID>& only)` —
  для пакетного этапа 2 (без волны потока). У частично загруженной сессии ставится флаг
  `m_partialEvents`; полная `StoreEventsToDatabase` для неё **запрещена** (иначе удалит
  незагруженные волны) — `qWarning` и отказ. Это обязательное требование безопасности.
- **`analysis_daily`** (схема **v20**, шаг миграции v19 → v20 — только `CREATE TABLE` и
  индекс; при MR согласовать номер версии с upstream). Одна строка на
  `(profile_id, date)`; `NULL` — показатель неприменим (нет потока или нет оксиметрии).
  Храним **счётчики и секунды**, а не индексы, чтобы корректно агрегировать периоды:
  - служебные: `id, profile_id, date, algo_version, params_hash, inputs_hash, computed_at`;
  - поток: `flow_s, flow_rate_hz, unscoreable_s, n_oa, n_ca, n_a, n_oh, n_ch, n_h, n_rera,
    n_unconfirmable, n_h_aasm3, n_h_cms4, n_h_flow, fl_time_s, fl_sum, n_fl_breaths,
    pb_time_s, hypopnea_rule`;
  - сравнение: `dev_apnea, dev_hypopnea, dev_rera, cmp_matched, cmp_device_only,
    cmp_analysis_only, cmp_type_mismatch`;
  - оксиметрия: `oxi_s, oxi_scope ('night'|'cpap'), oxi_source, has_cpap, n_desat3,
    n_desat4, spo2_hist (JSON: секунды по 50…100 %), spo2_sum, spo2_median, spo2_nadir,
    desat_area, linked_desat_area, n_unexplained_desat, n_cyclic, cyclic_s, n_zones,
    zone_s, zone_severe_s`;
  - пульс: `pulse_s, pulse_sum, pulse_sq_sum, pulse_min, pulse_max, pulse_hist (JSON:
    секунды по 30…220 уд/мин), n_pulse_rise, dhr_sum, n_dhr, brady_s, tachy_s`;
  - подсказка: `oxi_offset_hint_ms` (NULL — нет подсказки); `extra_json` — на будущее.
  - `FOREIGN KEY(profile_id) … ON DELETE CASCADE`, `UNIQUE(profile_id, date)`.
- Резервные копии `.oscar`: таблица **не экспортируется** (производные данные);
  после восстановления пересчитывается. Каналы этапа 1/2 уходят вместе с сессиями.
- Очистка дней (`purgerangedaysdialog`) удаляет строки этих дат.

### 4.4 Когда считается
- **Импорт CPAP/оксиметра:** этап 1 — в `Session::UpdateSummaries()` рядом с
  `calcSPO2Drop` (работает в пуле потоков, поэтому на вход — снимок `AnalysisParams`,
  а не чтение `p_profile` из потока); этап 2 — для затронутых дат после `Commit()`
  импорта (`MainWindow::importCPAP`, мастер оксиметра, BLE-импорт).
- **Открытие дня:** события дня всё равно загружены. Если штамп этапа 1 сессии устарел —
  пересчёт этапа 1 и точечная запись; если `inputs_hash` дня ≠ сохранённому — этап 2.
- **Инвалидация этапа 2** (`AnalysisService::invalidate(machine, dates)`):
  `TimeAlignSession::commit` / `Daily::afterAlignSaved`,
  `DeviceTimeCorrectionDialog::correctionsChanged`, `DriftAnalysisDialog::correctionsChanged`,
  «Purge all time corrections», включение/выключение сессии, удаление/очистка данных.
  Небольшое число дат — пересчёт сразу; диапазон — пакетно с прогрессом.
- **`inputs_hash`** дня = хеш (`kAnalysisAlgoVersion`, хеш параметров этапа 2; по каждой
  сессии дня: id, machine_id, enabled, штамп этапа 1, `correctionMs` её машины за ночь).
- **Пакетный пересчёт:** *Data → Recalculate Analysis…* (все дни или только устаревшие),
  модальный прогресс по дням с отменой (как `doReprocessEvents`), затем обновление вкладок.
  Устаревший этап 1 требует волн → полная загрузка событий дня; этап 2 — частичная.
- «Обзор» и «Статистика» читают `analysis_daily` через кэш `AnalysisService`
  (загружается при открытии профиля, обновляется при записи). Если есть дни со старой
  версией/параметрами — строка «Analysis is outdated for N days — Recalculate».

```
импорт ─► Session::UpdateSummaries ─► SessionAnalysis (этап 1) ─► EventList AN_* + AN_Stamp
      └─► после Commit ─► DayAnalysis (этап 2) ─► AN_*Hypopnea (точечно) + analysis_daily

Daily::Load ─► AnalysisService::ensureDay(day) ─► [этап 1 при устаревшем штампе] ─► [этап 2]
            ─► панель «Анализ», график флагов анализа, FL-график

поправка времени / вкл.-выкл. сессии / очистка ─► AnalysisService::invalidate ─► этап 2

Overview / Statistics ─► AnalysisService (кэш analysis_daily)
```

### 5.1 «День»
- **График «Analysis Flags»** сразу под «Event Flags»: `gFlagsGroup` с фильтром каналов
  (новый предикат); из основного «Event Flags» вычисленные каналы исключаются. Скрыт,
  если в дне нет каналов анализа. Имя — в `skipgraph` и в порядки графиков
  (`daily.cpp:104-133`, без повторов).
- **График «Flow Limitation (analysis)»** — `AN_FLScore` 0–1, рядом с графиком FL ResMed
  в расширенном порядке.
- **Наложения:** десатурации на SpO₂, подъёмы пульса на пульсе (§4.2).
- **Раздел боковой панели «Analysis (second opinion)»** — новый `LSB_ANALYSIS`
  (`daily.h:464`), HTML как в `getIndices`:
  - таблица «Device | Analysis»: AHI, индекс апноэ (OA/CA/A), индекс гипопноэ (OH/CH/H),
    RERA, FL (% времени), периодическое дыхание (% времени), знаменатели (часы);
  - оксиметрия: ODI 3 %/4 %, SpO₂ средняя/надир, таблица «время ниже порогов» и
    диапазонов (§3.2.7), проблемные зоны (число, суммарное время, выраженные), HB (approx.)
    и необъяснённые десатурации (только при CPAP), средняя глубина десатурации,
    источник SpO₂;
  - строка «Hypopnea index by rule: AASM 3 % … · CMS 4 % … · Flow only …» (§3.4.1);
  - пульс: средний/мин/макс, индекс подъёмов, ΔHR;
  - согласие с аппаратом: совпало / только аппарат / только анализ, ссылка
    «Show differences»;
  - примечания: какое правило гипопноэ применено, частота потока и что отключено,
    неоцениваемое время, «нет оксиметрии — гипопноэ по потоку», подсказка сдвига
    оксиметра со ссылкой `align=oximeter` (обработка в `Daily::Link_clicked`);
  - строка-предупреждение (§1).
- **Ночь только с оксиметром:** раздел показывает только оксиметрию и пульс; главный
  блок — проблемные зоны и время ниже порогов; строки CPAP и сравнения скрыты.
- **Вкладка «Analysis»** в левой панели (рядом с Events): дерево «Problem zones» /
  «Device only» / «Analysis only» / «Type mismatch» / «Unexplained desaturations»; у зон в
  подписи — время, длительность, минимум SpO₂, число десатураций; у элементов
  `Qt::UserRole` = время в мс; щелчок → `GraphView->SetXBounds(...)`, как
  `on_treeWidget_itemClicked` (`daily.cpp:2901`).

### 5.2 «Обзор»
Графики на основе `gSummaryChart` (образец — `gTTIAChart`), данные из кэша
`analysis_daily`:
1. «AHI: device vs analysis» (две серии);
2. «ODI 3 % / 4 %»;
3. «SpO₂ time in ranges» — столбик на ночь, сложенный по диапазонам §3.2.7 (мин);
4. «Oximetry problem zones» (мин за ночь, выраженные — отдельным цветом);
5. «Hypoxic burden (approx.)»;
6. «Flow limitation (analysis)» (% времени);
7. «Pulse rise index».
Графики скрываются, если за период нет данных; видимость — через штатное меню графиков.
Оксиметрические графики включают ночи только с оксиметром.

### 5.3 «Статистика»
Раздел «Analysis (second opinion)» (показывается при наличии данных): AHI анализа,
индексы OA/CA/A, индекс гипопноэ, индекс RERA, % FL, ODI3, ODI4, % времени ниже каждого
порога SpO₂, время в проблемных зонах, надир SpO₂ (минимум за период), HB, индекс подъёмов
пульса, ΔHR, согласие с аппаратом. Агрегация за период —
сумма счётчиков / сумма часов (не среднее дневных индексов). Реализация: новый тип
`SC_ANALYSIS` в `StatCalcType` с ключом показателя в `src`, ветка в
`StatisticsRow::value()`.

### 5.4 Настройки
Новая вкладка «Analysis» в `PreferencesDialog`:
- включить анализ;
- **правило гипопноэ — селектор с описанием**: `QComboBox` и под ним `QLabel` с переносом
  строк, текст меняется при выборе (и дублируется во всплывающей подсказке). Тексты
  (английский в `tr()`, русский перевод в `.ts`):
  - **Auto (recommended)** — «AASM 3 % where the oximeter covers the event, Flow only
    elsewhere. Good when you wear an oximeter only on some nights.»
  - **AASM 3 %** — «Current sleep-lab standard (AASM 2012, rule 1A). A ≥ 30 % drop in flow
    for ≥ 10 s counts as a hypopnea only if SpO₂ then falls by ≥ 3 %. Arousals, which a
    sleep lab also accepts, are invisible to OSCAR, so this can count slightly fewer
    hypopneas than a lab. Needs an oximeter; without one, events are scored as Flow only.»
  - **CMS 4 %** — «Stricter rule used by US Medicare (AASM rule 1B). Same flow drop, but
    SpO₂ must fall by ≥ 4 %. Gives fewer hypopneas and a lower AHI than AASM 3 % for the
    same night; use it to compare with studies or reports scored this way.»
  - **Flow only** — «No oximeter needed. A ≥ 50 % drop in flow for ≥ 10 s counts, similar
    to how CPAP devices score hypopneas. Cannot tell whether the drop affected oxygen.»
  - под описаниями — примечание: «The Analysis panel always shows the hypopnea index
    under all three rules, so you can compare them on your own nights.»
- ограничить оксиметрию временем CPAP (по умолчанию выкл.);
- пороги SpO₂ для «времени ниже» (список), пороги проблемных зон;
- подъём пульса как пробуждение; классификация апноэ;
- блок «Advanced» со всеми порогами §3.5; «Reset to defaults».

Изменение — вопрос о пересчёте (этап 1 и/или 2 по тому, какие хеши изменились); смена
порогов «времени ниже» пересчёта не требует (гистограммы, §3.2.7). Настройки — класс
`AnalysisSettings : PrefSettings` (`p_profile->analysis`), ключи `STR_AN_*` в `profiles.h`.

## 6. Ошибки и крайние случаи

| Ситуация | Поведение |
|---|---|
| Нет потока или `fs < 4 Гц` | Анализ потока не выполняется; в панели «Flow analysis unavailable (sample rate N Hz)» |
| `4 ≤ fs < 10 Гц` (PRS1 ~5 Гц) | Нет FL и кардиогенных осцилляций; апноэ только OA/CA по контексту или aA |
| Нет оксиметрии | Гипопноэ по Flow only; оксиметрические разделы скрыты; в «Обзоре» пропуски |
| Ночь только с оксиметром | Полный анализ оксиметрии и пульса, проблемные зоны, время ниже порогов; CPAP-разделы, HB и сравнение скрыты |
| Оксиметр есть, но смещён | Подсказка сдвига (§3.4.7); после выравнивания — пересчёт этапа 2 |
| Несколько CPAP за ночь | Анализируются все; события и часы суммируются |
| Несколько источников SpO₂ | Берётся источник с наибольшим валидным временем (§3.1) |
| Prisma без данных о снятии маски | Исключение по спанам артефактов/критической утечки и по «длинному снижению» |
| Сессия частично загружена | Полная запись событий запрещена (§4.3) |
| Ошибка записи в БД | `qCritical` + `checkQueryError`; день помечается устаревшим, интерфейс не падает |
| Пересчёт отменён | Уже пересчитанные дни сохраняются; остальные остаются устаревшими |
| Сессия выключена/удалена | Инвалидация этапа 2 за эту дату |
| Длинное событие > 120 с | Не событие, а неоцениваемый участок |
| Сбой алгоритма (исключение, NaN) | Лог, анализ этой сессии пропускается, остальное работает |

## 7. Тестирование

### 7.1 Автотесты (`qmake CONFIG+=test`, `DECLARE_TEST`)
Синтетические сигналы (генераторы в `tests/analysis_synth.{h,cpp}`):
1. `signal_utils`: сетка 1 Гц из списков «по изменению» и волны; скользящий перцентиль
   против наивного; медианный фильтр; прореживание.
2. `OxiAnalyzer`: база 96 % — падения 2 % (нет), 3 % на 20 с (только ODI3), 5 % на 30 с
   (оба); серия 5 падений через 45 с (циклический эпизод); дрейф 96 → 89 за 10 мин (не
   событие, но T90); одиночный выброс 70 (игнорируется); разрывы; точные секунды T90.
3. Пульс: подъём на 10 уд/мин за 5 с на 10 с (одно событие), на 4 (нет); брадикардия.
3a. Гистограммы и «время ниже порогов»: точные секунды на синтетике, смена списка порогов
    без пересчёта. Проблемные зоны: серия из 4 десатураций за 4 мин → одна зона;
    90 с ниже 90 % → зона тяжести 1; 40 с ниже 85 % → тяжести 2; две зоны с промежутком
    1 мин → слияние; одиночная десатурация → нет зоны; ночь без CPAP — всё считается.
4. `FlowAnalyzer` (синусоида 0,25 Гц, 25 и 5 Гц): апноэ 15 с (амплитуда 3 %) → апноэ с
   точностью ±1 с; снижение 50 % на 20 с → кандидат ≈ 50 %; 25 % → нет; апноэ 8 с → нет;
   маска снята 5 мин (нули) → неоцениваемо, не апноэ; при 5 Гц FL выключен.
5. FL: синус → FL < 0,2; срезанная на 70 % синусоида → ≥ 0,5; M-форма → ≥ 0,5; «кресло».
6. Классификатор: центральное апноэ с осцилляциями 1,2 Гц → aCA; апноэ после FL-дыханий
   с резким восстановлением → aOA; без свидетельств → aA.
7. Периодическое дыхание: модуляция с периодом 60 с на 20 мин → эпизод; шум → нет.
8. `EventMatcher`: перекрытие, допуск ±5 с, жадность, расхождение типа, соглашение
   «начало/конец».
9. `DayScorer`: правила AASM3/CMS4/Flow only/Auto; кандидат без SpO₂; границы окна связи;
   HB; ΔHR; поправки времени сдвигают связь; подсказка находит лаг +120 с.
10. `AnalysisDailyRepository` на временной БД (`QTemporaryDir`, как `applehealthtests`):
    upsert/чтение/удаление; миграция v19 → v20.
11. Интеграция: сессия с синтетическим потоком → этап 1 → каналы, штамп; вычисленные
    каналы не попадают в `reportedChannels`; `StoreChannelEvents` не трогает волну;
    частично загруженная сессия не пишется полностью.

### 7.2 Ручное тестирование — только на копии данных
1. `cp -R ~/Documents/OSCAR20_Data ~/Documents/OSCAR20_Data_dev`, запуск с
   `--datadir OSCAR20_Data_dev` (схема обновится до v20 — необратимо).
2. **Проверки соглашений:** знак потока ResMed и Prisma; частота `RespFlow` Prisma;
   медиана смещения совпавших апноэ ResMed (onset или конец?) — по итогу правится
   таблица `DeviceEventConvention`.
3. **Настройка порогов** на ≥ 30 ночах ResMed и Prisma: согласие апноэ, соотношение
   AHI, корреляция FL с ResMed FLG, OA/CA против классификации аппарата (FOT). Если
   OA/CA согласуются < 70 % — классификация по умолчанию выключается. Итоги — в
   `SLEEP_ANALYSIS.md`.
4. Чек-лист: флаги и графики «Дня», панель и вкладка расхождений, переходы по щелчку;
   выравнивание оксиметра → гипопноэ и HB пересчитались; подсказка сдвига на искусственно
   смещённой ночи; «Обзор» и «Статистика» за год — скорость; смена настроек → пересчёт;
   *Recalculate Analysis…* с отменой; импорт новой карты — анализ появился; AHI и
   статистика аппарата не изменились; OH/CH устройства ведут себя как раньше.

### 7.3 Сборка в этой среде
Проект требует Qt ≥ 6.5 (`QTimeZone::LocalTime` и др.); в облачной среде доступна только
Qt 6.4 из apt, а `download.qt.io` закрыт сетевой политикой. Поэтому здесь анализаторы
(QtCore) и их тесты собираются отдельным тестовым `.pro` во временной папке; полная сборка
и тесты проекта — у пользователя (или после открытия доступа к `download.qt.io`).

## 8. Этапы и коммиты
Одна ветка, каждый коммит собирается и проходит тесты.

**A. Движок (без интерфейса)**
1. `Fix SpO2 drop depth and pulse change magnitude` — отдельный, пригоден для MR сам по себе.
2. `Add analysis parameters and signal utilities`
3. `Add oximetry analyzer: desaturations, cycles, pulse rises`
4. `Add flow analyzer: breaths, envelope, apnea and hypopnea candidates`
5. `Add flow limitation scoring, flow RERA and periodic breathing`
6. `Add heuristic apnea classification`

**B. Интеграция и хранение**
7. `Add analysis channels and exclude computed channels from device capabilities`
8. `Run session analysis on import; targeted channel store and partial event loading`
9. `Add analysis_daily table (schema v20) and repository`
10. `Add day scoring: hypopnea rules, desaturation linkage, comparison with device events`
11. `Add AnalysisService: lazy and batch recalculation, invalidation on time corrections`

**C. Интерфейс**
12. `Show analysis flags and flow limitation graphs in Daily view`
13. `Add Analysis sidebar section and differences tab to Daily view`
14. `Add analysis charts to Overview`
15. `Add analysis section to Statistics`
16. `Add Analysis preferences and Data > Recalculate Analysis`
17. `Add Analysis per day report, developer notes and Russian translations`

MR в upstream (`CrimsonNape/oscar-sql`) **отложен** до прогона всех тестов и ручной
проверки на реальных данных ResMed и Prisma; до этого работа живёт в форке. Порядок MR
решим тогда же. Эта спецификация и план в MR не входят.

## 9. Вне рамок (YAGNI)
- Стадии сна и пробуждения по ЭЭГ; машинное обучение.
- Смешанные апноэ как отдельный класс.
- Анализ плетизмограммы (амплитуда пульсовой волны) — Contec по BLE её не отдаёт.
- Автоматическое применение сдвига оксиметра (только подсказка).
- Ручная разметка/редактирование событий, импорт разметки ПСГ (EDF+) для валидации.
- Пересчёт или замена AHI аппарата; изменение событий аппарата.
- PDF-отчёт по анализу.

## 10. Решения по вопросам ревью (2026-09-28)
1. Правило гипопноэ — **селектор с подробным описанием разницы** (§5.4); по умолчанию
   Auto; в панели всегда видны индексы по всем трём правилам.
2. Оксиметрия **не ограничивается** временем CPAP по умолчанию (опция); ночь только с
   оксиметром — полноценный сценарий: проблемные зоны (§3.2.8) и время ниже порогов (§3.2.7).
3. Классификация апноэ **включена** по умолчанию; выключается, если на данных пользователя
   согласие OA/CA с аппаратом < 70 %.
4. Отправка в upstream **отложена** до прогона всех тестов.
