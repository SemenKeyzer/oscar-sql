- Дата: 2026-10-02

- Источник задачи: `plans/2026-10-01-handoff.md`, раздел 4.2, пункт 4 («Сравнение до / после»)

## 1. Цель и контекст

### Задача
Понять, помогла ли смена настроек аппарата. Владелец выбрал этот сценарий первым;
одностраничный PDF для врача — следующий, отдельный подпроект. Он будет строиться на этом
сравнении.

### Почему таблица, а не «до / после»
У отца владельца (Löwenstein Prisma 20A, профиль «Папа») настройки меняются каждые 1–3 ночи.
За две недели сентября 2026 — 12 периодов: APAP 9–16 три раза с разным softPAP, затем
6–9, 7–10, 7.5–11, 7.5–12. Сравнение «одного периода до» с «одним периодом после» по одной
ночи бессмысленно: разброс между ночами больше эффекта от настройки. Поэтому нужна таблица
всех настроек, где одинаковые настройки собраны в одну строку, а строки с малым числом
ночей явно помечены.

### Что уже есть
- `Statistics::updateRXChanges()` (`statistics.cpp`) делит историю на непрерывные периоды
  `RXItem`. Новый период начинается, когда меняются режим (`Day::getCPAPModeStr`),
  давление (`getPressureSettings`), сброс давления (`getPressureRelief`) или аппарат
  (`sameDevice`: с `AppSetting->combineSimilarMachines()` — марка, иначе тот же `Machine*`).
  У периода есть даты (`rx.dates`), часы, суммы событий, в том числе для AHI и RDI.
  Периоды кэшируются в `RXChanges.cache`.
- `Statistics::GenerateRXChanges()` показывает эти периоды таблицей «Изменения настроек
  аппарата». По каждому периоду там только AHI и индекс FL аппарата.
- `analysisFigure(key, rows)` (`statistics.cpp`) считает показатели собственного анализа
  OSCAR по любому списку строк `AnalysisDailyData`: `ahi`, `fl`, `odi3`, `below:<порог>` и
  другие. Строки по датам отдаёт `AnalysisService::rows(start, end)`.
- В «Статистике» три режима отчёта: `STAT_MODE_STANDARD`, `STAT_MODE_MONTHLY`,
  `STAT_MODE_RANGE` (`profiles.h`). Это радиокнопки `reportModeStandard / Monthly / Range` в
  `mainwindow.ui`. Режим хранится в `p_profile->general->statReportMode()`.
- `Statistics::printReport()` печатает `htmlReportHeaderPrint + htmlUsage + …`, то есть то,
  что собрал последний `GenerateHTML()`.

## 2. Что видит пользователь

### Режим «Настройки»
- Внизу «Статистики» добавляется четвёртая радиокнопка — «Настройки» (`STAT_MODE_SETTINGS = 3`).
  Она стоит после «Период». Выбранный режим запоминается так же, как остальные.
- Выбор дат в этом режиме скрыт: таблица всегда строится по всей истории.
- Страница: обычная шапка «Статистики», под ней одна таблица на всю ширину, затем обычный
  подвал. Блоки «Использование CPAP», «Изменения настроек аппарата» и «Информация об
  аппарате» в этом режиме не показываются.

### Таблица «Сравнение настроек аппарата»
- Колонки (подписи из перевода):

  | Колонка | Содержимое |
  |---|---|
  | Настройки | одной строкой: режим, давление, сброс давления, например «APAP (дин) · Мин 7.5 Макс 12.0 (см H2O) · SoftPAP: 1 - Слабый» |
  | Аппарат | только если в истории больше одного аппарата (или марки при объединении) |
  | Ночей | число ночей |
  | Исп., ч | среднее время использования за ночь |
  | AHI аппарата | RDI, если в профиле включён RDI; подпись меняется так же, как в нынешней таблице |
  | AHI анализа | AHI собственного анализа OSCAR |
  | Утечка | средняя утечка |
  | Давление 95 % | процентиль из настроек профиля (`prefCalcPercentile`); подпись — «Давление %1 %» |
  | Огр. потока | собственный анализ, % времени |
  | ODI 3 % | собственный анализ, событий в час |
  | SpO2 < 90 % | собственный анализ, % времени |

- **Склейка.** Строка — уникальное сочетание «режим, давление, сброс давления, аппарат».
  Сюда попадают все периоды с этим сочетанием, даже несмежные. При наведении на ячейку
  «Настройки» подсказка перечисляет даты, из которых собрана строка, например
  «20.09.2026; 21.09.2026 – 23.09.2026».
- **Порядок.** Сверху строки, использованные позже всех: по последней ночи строки, от новых к
  старым.
- **«Мало ночей».** Строки, где меньше 3 ночей (`kMinNights = 3`), показаны серым текстом. В
  колонке «Ночей» у них пометка «мало ночей».
- **Лучшее значение** в колонке подсвечено зелёным фоном. Учитываются только строки с
  3 и более ночами. При равенстве подсвечиваются все равные. Если таких строк меньше двух,
  подсветки в колонке нет.
  - Меньше — лучше: AHI аппарата, AHI анализа, утечка, ограничение потока, ODI 3 %, SpO2 < 90 %.
  - Больше — лучше: использование.
  - Давление и «Ночей» не подсвечиваются.
- **Нет данных.** Если в строке нет данных для колонки, стоит «–». Например, нет ночей с
  оксиметром или анализ ещё не посчитан.
- **Устаревший анализ.** Если анализ устарел хотя бы для одной ночи, над таблицей та же
  строка, что в стандартном режиме: «Анализ устарел для N дней. Пересчитать», со ссылкой
  `analysis=recalculate`. Плюс дисклеймер анализа
  (`AnalysisPanel::disclaimer()`), так как в таблице цифры анализа.
- **Пояснение** под таблицей (курсивом):
  - лучшие значения отмечены зелёным среди настроек с 3 и более ночами;
  - серые строки — меньше 3 ночей, по ним выводы делать рано;
  - давление — среднее по ночам.
- **Печать.** Существующая кнопка «Печать» печатает этот режим так же, как остальные.

## 3. Расчёт колонок

Для строки берутся её ночи (`dates`) и сумма по её периодам.

| Колонка | Расчёт |
|---|---|
| Ночей | число дат |
| Исп., ч | Σ `rx.hours` ÷ ночи |
| AHI аппарата | Σ `rx.ahi` (или `rx.rdi`) ÷ Σ `rx.hours`, как в `GenerateRXChanges` |
| AHI анализа | `analysisFigure("ahi", строки анализа за даты строки)` |
| Огр. потока | `analysisFigure("fl", …)` |
| ODI 3 % | `analysisFigure("odi3", …)` |
| SpO2 < 90 % | `analysisFigure("below:90", …)` |
| Утечка | Σ(`day->wavg(CPAP_Leak)` × часы ночи) ÷ Σ часы ночей, где есть канал утечки |
| Давление 95 % | Σ(`day->percentile(CPAP_Pressure, p)` × часы) ÷ Σ часы ночей с каналом давления; `p` = `prefCalcPercentile / 100` |

- Строки анализа за даты строки: один вызов `AnalysisService::rows(first, last)` за всю
  историю, затем фильтр по множеству дат строки.
- Чтобы получать число, а не текст, `analysisFigure` делится на две функции:
  `analysisFigureValue(key, rows)` возвращает `double`, а при отсутствии данных — NaN;
  `analysisFigure` форматирует результат как сейчас. Поведение стандартного режима не
  меняется.
- **Давление — среднее ночных процентилей.** Это быстро (сводки сессий) и одинаково
  считается для несмежных ночей. Цифра может немного отличаться от «Статистики» за тот же
  период: там процентиль считается по всем событиям сразу. Подсказка заголовка колонки об
  этом говорит.
- **Утечка и давление** берутся из `Day` той же ночи. У ночи без канала (`!channelHasData`)
  он не учитывается. Если у строки нет ни одной такой ночи, стоит «–».
- Числа: часы и AHI — 2 знака после запятой, проценты — 1 знак, утечка и давление — 1 знак.
  Формат локали (`QLocale().toString`), как в остальной «Статистике».

## 4. Устройство

### Новый модуль `oscar/settingscomparison.{h,cpp}`
Без зависимостей от `Profile`, `Day` и виджетов, только Qt Core и строки перевода. Проверяется
отдельно.
- `struct Period` — один непрерывный период:
  - режим, давление, сброс давления;
  - ключ аппарата и его подпись;
  - даты;
  - часы и сумма событий AHI.
- `QList<Group> group(const QList<Period> &)` — склеивает периоды с равными
  `(режим, давление, сброс давления, ключ аппарата)`. Даты объединены и отсортированы,
  часы и события сложены. Порядок — по последней дате, от новых к старым.
- `enum Column` — колонки таблицы. `struct Row` — группа и значения колонок (`double`, NaN —
  нет данных).
- `kMinNights = 3`; `bool reliable(const Row &)`.
- `QSet<int> best(const QList<Row> &, Column)` — номера строк с лучшим значением по
  правилам из §2.
- `QString dateList(const QList<QDate> &)` — даты строки, подряд идущие свёрнуты в диапазоны.
- `QString html(const QList<Row> &, const Options &)` — таблица целиком. В `Options`:
  - показывать ли колонку «Аппарат»;
  - подпись AHI или RDI;
  - процентиль давления;
  - цвета шапки и строк, как в «Статистике».

### Сборка в `Statistics`
`QString Statistics::GenerateSettingsComparison()`:
1. Вызывает `updateRXChanges()` (периоды и кэш как сейчас).
2. Превращает каждый `RXItem` в `Period`. Ключ аппарата: марка при
   `combineSimilarMachines()`, иначе модель и серийный номер; подпись — как в
   `GenerateRXChanges`.
3. Вызывает `group()`.
4. Считает колонки по §3 через `Day` и строки анализа.
5. Отдаёт `html()` и добавляет строку об устаревшем анализе и дисклеймер.

`GenerateHTML()` в режиме `STAT_MODE_SETTINGS` кладёт результат в `htmlUsage`, а
`htmlMachineSettings` и `htmlMachines` очищает. Так `printReport()` печатает этот режим без
изменений.

### Интерфейс
- `profiles.h`: `STAT_MODE_SETTINGS = 3`.
- `mainwindow.ui`: радиокнопка `reportModeSettings` («Настройки») после `reportModeRange`.
- `mainwindow.cpp`:
  - `on_reportModeSettings_clicked()` по образцу соседних;
  - в переключателе режимов ветка `STAT_MODE_SETTINGS` скрывает `statStartDate`,
    `statEndDate` и `statEnableEndDisplay`.
- Перевод: все новые строки — в `Translations/Russkiy.ru.ts`, без «unfinished»;
  `validate_ts.py` → TOTAL 0.

## 5. Граничные случаи
- **Нет CPAP-аппаратов или периодов:** как стандартный режим без данных (`htmlNoData()`).
- **Одна строка:** таблица из одной строки без подсветки.
- **Все строки меньше 3 ночей:** подсветки нет, пояснение остаётся.
- **Анализ не считался вообще:** колонки анализа — «–», строки «анализ устарел» нет, если
  `outdatedCount` = 0.
- **Ночи без CPAP-сессий** не попадают в периоды — так уже работает `updateRXChanges`.
  Если у строки всё же 0 часов, колонки «в час» и «за ночь» показывают «–», а не деление на 0.
- **Режим RDI:** колонка «AHI аппарата» показывает RDI, подпись «RDI».
- **Разные аппараты с одинаковыми настройками** не склеиваются. Колонка «Аппарат» нужна,
  чтобы их различать.
- **Дата отчёта** (`statReportDate`) в этом режиме не применяется: вся история.

## 6. Тесты
`tests/settingscomparisontests.{h,cpp}`, на подставных `Period` без профиля:
- несмежные периоды с одинаковыми настройками склеиваются: даты объединены, часы и события
  сложены;
- разные аппараты (ключи) или разный сброс давления не склеиваются;
- порядок — по последней ночи, от новых к старым;
- `best()`:
  - «меньше — лучше» и «больше — лучше»;
  - строки меньше 3 ночей не участвуют;
  - равные значения подсвечиваются вместе;
  - меньше двух надёжных строк — пусто;
  - давление не подсвечивается;
- `dateList()` сворачивает подряд идущие даты в диапазон;
- `html()`:
  - NaN → «–»;
  - серая строка и «мало ночей» на 1–2 ночах;
  - зелёная ячейка у лучшего;
  - колонка «Аппарат» только при нескольких аппаратах;
- `analysisFigureValue()`: NaN без данных; то же число, что текст `analysisFigure()`.

Проверка глазами в приложении на профиле «Папа»:
- строки 9–16 со «слабым» softPAP (20.09 и 21–23.09) склеены, 4 ночи;
- однодневные периоды серые;
- печать в PDF содержит таблицу.
