## 1. Цель и контекст

### Задача
Отец владельца (профиль «Папа», Löwenstein Prisma 20A, оксиметр Contec CMS50FW) ходит к
сомнологу, который подбирает давление. Вопрос визита — «какие настройки оставить». Врачу нужна
одна страница, по которой за минуту видно:
- что стоит сейчас и с какого числа;
- работает ли терапия: использование, AHI, утечка, давление, кислород;
- как ночи реагировали на смены настроек;
- как прошли ночи на каждой из настроек.

Владелец выбрал:
- сценарий — «подбор настроек»;
- период — даты выбираются перед сохранением, по умолчанию последние 30 дней;
- все четыре блока: итог с целями, график по ночам, таблица сравнения настроек, цифры
  анализа OSCAR.

### Что уже есть
- `Statistics::printReport()` печатает HTML «Статистики» через `QTextDocument` в `QPrinter`.
  `Report::PrintReport()` (`reports.cpp`) рисует «День» и «Сводку» через `QPainter`.
  Одностраничного отчёта нет.
- `SettingsComparison` (`settingscomparison.{h,cpp}`) склеивает периоды настроек, выбирает
  лучшие значения и рисует HTML-таблицу. `Statistics::GenerateSettingsComparison()` собирает для
  неё строки по всей истории.
- `NightSummary` (`nightsummary.{h,cpp}`) задаёт цели стартового экрана:
  - `kAhiTarget = 5`;
  - `kOdiTarget = 5`;
  - `kT90Target = 5`.

  Там же `NightSummary::Level` (`Unknown / Good / Attention`) и
  `NightSummaryView::levelColor()`.
- `analysisFigureValue(key, rows)` (`statistics.cpp`) — показатели анализа по строкам
  `AnalysisDailyData`.
- Профиль хранит:
  - `user->firstName()`, `lastName()`, `DOB()`;
  - `cpap->complianceHours()`, `cpap->leakRedline()`;
  - `general->prefCalcPercentile()`, `general->calculateRDI()`.

  `AppSetting->showPersonalData()` решает, показывать ли личные данные.

## 2. Что видит пользователь

### Запуск
- Меню «Файл» → «Отчёт для врача (PDF)…» — сразу после «Печать».
- Окно «Отчёт для врача»:
  - поля «с» и «по» (`QDateEdit` с календарём) в пределах первой и последней даты профиля;
  - кнопки «Сохранить PDF…» и «Отмена».
- По умолчанию:
  - «по» — последняя ночь с данными CPAP (`p_profile->LastDay(MT_CPAP)`);
  - «с» — сохранённое в профиле значение (`DoctorReportFrom`), если оно не позже «по»; иначе
    «по» минус 29 дней.
- «Сохранить PDF…» недоступна, пока «с» позже «по».
- По «Сохранить PDF…» открывается выбор файла в «Документах». Имя по умолчанию —
  `Отчёт CPAP <профиль> <с dd.MM>–<по dd.MM.yyyy>.pdf`, например «Отчёт CPAP Папа 03.09–02.10.2026.pdf».
- После сохранения:
  - «с» записывается в профиль;
  - сообщение «Отчёт сохранён» с кнопкой «Открыть» (`QDesktopServices::openUrl`).
- **Нет ночей CPAP в выбранных датах:** сообщение «За эти даты нет ночей с данными CPAP».
  Файл не создаётся, окно остаётся открытым.

### Страница (A4 вертикально, поля 12 мм)
1. **Шапка**
   - Заголовок «Отчёт о CPAP-терапии».
   - Пациент: «Имя Фамилия, дата рождения 01.01.1954» — только при `showPersonalData()`.
     Без этого строки «Пациент» нет вовсе.
   - Аппарат: марка и модель; серийный номер — при `AppSetting->includeSerial()`. Если в
     периоде было несколько аппаратов, они перечислены через запятую.
   - Оксиметр: модель. Строка есть, только если в периоде были ночи с оксиметром.
   - Период: «03.09.2026 – 02.10.2026 · ночей с данными 25 из 30 · с оксиметром 6».
   - **Текущие настройки** (выделены рамкой): «APAP (дин) · Мин 7.5 Макс 12.0 (см H2O) ·
     SoftPAP: 1 - Слабый — с 01.10.2026».
2. **Итог за период** — шесть плиток в два ряда по три. У каждой плитки:
   - цветная полоса слева (`NightSummaryView::levelColor`);
   - знак ✓ или «!»;
   - подпись, крупное число и строка пояснения.

   | Плитка | Число | Пояснение | Цель (✓) |
   |---|---|---|---|
   | Использование | средние часы за ночь с данными | «N из M ночей ≥ 4 ч» (часы — из профиля) | среднее ≥ `complianceHours` |
   | AHI | AHI аппарата (RDI при `calculateRDI`) | «анализ OSCAR: X · огр. потока Y %» | < 5 |
   | Утечка | средняя, с единицами канала | «красная линия Z» или «красная линия не задана» | < `leakRedline` |
   | Давление | «Давление 95 %» (процентиль профиля) | «среднее по ночам» | — (без оценки) |
   | ODI 3 % | событий в час | «по ночам с оксиметром» | < 5 |
   | SpO2 < 90 % | % времени | «по ночам с оксиметром» | < 5 % |

   Если оценить нельзя (нет данных, не задана красная линия, давление), плитка серая и без
   знака. Нет данных — вместо числа «–».
3. **График по ночам** — картинка во всю ширину, около 55 мм высотой.
   - Верхняя полоса — AHI аппарата за каждую ночь:
     - столбики зелёные (< 5) или оранжевые (≥ 5);
     - пунктирная линия на 5.
   - Нижняя полоса — часы использования:
     - столбики синие (≥ `complianceHours`) или оранжевые (меньше);
     - пунктир на `complianceHours`.
   - Ночь без данных — пустое место.
   - Серая вертикальная пунктирная линия на левом краю ночи, с которой начался новый период
     настроек. Первая ночь периода отчёта не отмечается.
   - Подписи дат (dd.MM) внизу — не чаще одной на ~10 мм. Подписи максимумов осей слева.
4. **Сравнение настроек** — таблица `SettingsComparison::html()` только по ночам периода, с
   теми же правилами (лучшие значения, «мало ночей», «–»).
5. **Подвал** (мелко):
   - дисклеймер анализа (`AnalysisPanel::disclaimer()`);
   - «Отчёт подготовлен OSCAR <версия>, <дата и время>».

Отчёт рассчитан на одну страницу при таблице до 12 строк. Длиннее таблица переходит на вторую
страницу; ничего не обрезается.

## 3. Расчёты

Ночь периода — дата в `[с, по]`, где у дня есть CPAP-сессии и `day->hours(MT_CPAP) > 0`.

| Показатель | Расчёт |
|---|---|
| Ночей с данными | число таких ночей |
| Дней в периоде | `с.daysTo(по) + 1` |
| Ночей с оксиметром | строки анализа периода с `hasOximetry` |
| Использование | Σ часов ÷ ночей; «≥ 4 ч» — число ночей с часами ≥ `complianceHours` |
| AHI аппарата | Σ `day->count(AllAhiChannels)` (+ `CPAP_RERA` для RDI) ÷ Σ часов |
| AHI анализа, огр. потока, ODI 3 %, SpO2 < 90 % | `analysisFigureValue("ahi" / "fl" / "odi3" / "below:90", строки анализа периода)` |
| Утечка | Σ(`day->wavg(CPAP_Leak)` × часы) ÷ Σ часов ночей с каналом утечки |
| Давление 95 % | Σ(`day->percentile(CPAP_Pressure, p)` × часы) ÷ Σ часов ночей с каналом давления |

- Часы — всегда только CPAP (`hours(MT_CPAP)`), без оксиметра.
- **Сравнение настроек за период.** Каждый период настроек `RXItem` урезается до ночей внутри
  `[с, по]`. Пустые отбрасываются. Часы и события считаются заново по оставшимся ночам, так
  что частично попавший период учитывается правильно. Затем `SettingsComparison::group()` и
  расчёт колонок, как в режиме «Настройки». Режим «Настройки» использует ту же функцию за всю
  историю.
- **Смены настроек на графике** — даты начала периодов `RXItem`, попавшие в `(с, по]`.
- **Текущие настройки** — период `RXItem`, которому принадлежит последняя ночь периода отчёта.
  Его подпись (режим · давление · `formatRelief(relief)`) и `rx.start` — «с какого числа».
  Может быть раньше «с».

## 4. Устройство

### Модуль `oscar/doctorreport.{h,cpp}` — модель и отрисовка
Зависит от Qt Core и Gui (`QImage`, `QPainter`), `PrintSupport` (`QPrinter`),
`SettingsComparison`, а также `NightSummary` и `NightSummaryView` (цели, цвета). Не зависит от
`Profile`, `Day` и `MainWindow`.

- `struct DoctorReport` — все данные страницы:
  - шапка: `patient`, `birthDate`, `cpapDevices`, `oximeter`;
  - период: `from`, `to`, `nights`, `oximetryNights`;
  - настройки: `currentSettings`, `settingsSince`;
  - итоги: `meanHours`, `compliantNights`, `complianceHours`, `deviceAhi`, `analysisAhi`,
    `flowLimitation`, `leak`, `leakUnits`, `leakRedline`, `pressure`, `percentile`, `odi3`,
    `below90`, `ahiName`;
  - ночи: `QVector<Night> { QDate date; double hours; double ahi; }`;
  - `settingsChanges`;
  - сравнение: `QList<SettingsComparison::Row> comparison`, `showDevice`.

  NaN — нет данных.
- Уровни плиток: `usageLevel()`, `ahiLevel()`, `leakLevel()`, `odiLevel()`, `below90Level()`
  возвращают `NightSummary::Level` по правилам §2.
- `QImage chart(const DoctorReport &, const QSize &)` — график §2.3.
- `QString html(const DoctorReport &, const QString &chartUrl)` — страница целиком; график —
  `<img src=chartUrl>`.
- `bool writePdf(const DoctorReport &, const QString &path, QString *error)`:
  1. `QPrinter(HighResolution)`, `PdfFormat`, A4, поля 12 мм;
  2. `QTextDocument` с `html()`, картинка графика — ресурсом документа;
  3. `print()`.

### Сборщик в `Statistics`
- `QList<SettingsComparison::Row> Statistics::settingsComparisonRows(const QDate &from, const QDate &to, bool *showDevice)`
  — выносится из `GenerateSettingsComparison()` с урезанием по датам (§3).
  `GenerateSettingsComparison()` вызывает её с `FirstDay()`…`LastDay()`.
- `DoctorReport Statistics::doctorReport(const QDate &from, const QDate &to)` заполняет модель
  по §3. Опирается на `updateRXChanges()`, `analysisRows()`, `analysisFigureValue()`,
  `p_profile`, `AppSetting`.

### Окно `oscar/doctorreportdialog.{h,cpp}`
- `QDialog` с двумя `QDateEdit` и кнопками.
- Значения по умолчанию и запоминание «с» — по §2. Ключ профиля: `STR_US_DoctorReportFrom =
  "DoctorReportFrom"` в `UserSettings`.
- Сохранение:
  1. `QFileDialog::getSaveFileName`;
  2. `Statistics().doctorReport()`;
  3. проверка `nights > 0`;
  4. `writePdf()`;
  5. сообщение с «Открыть».

### Меню
`mainwindow.ui`: действие `actionDoctor_Report` «Отчёт для врача (PDF)…» после
`actionPrint_Report`. Слот в `mainwindow.cpp` открывает окно. Пункт недоступен без профиля,
как «Печать».

### Перевод
Все новые строки — в `Translations/Russkiy.ru.ts` без «unfinished»;
`validate_ts.py` → `TOTAL 0`.

## 5. Граничные случаи
- **Нет ночей CPAP в датах:** сообщение, файл не создаётся (§2).
- **Нет оксиметрии в периоде:** нет строки «Оксиметр»; плитки ODI и SpO2 серые с «–»; в шапке
  «с оксиметром 0».
- **Анализ не считался или устарел:** «–» в цифрах анализа. Отчёт всё равно строится —
  пересчёт остаётся в приложении.
- **Красная линия утечки не задана** (`leakRedline() <= 0`): плитка утечки серая, пояснение
  «красная линия не задана».
- **Нет канала давления** (BiLevel и др.): «–» в плитке давления.
- **Режим RDI:** плитка и колонка подписаны «RDI».
- **Личные данные выключены:** нет строки «Пациент».
- **Длинный период** (например, год): столбики не уже 1 пикселя, подписи дат прореживаются.
- **Не удалось записать файл:** сообщение с текстом ошибки, окно остаётся открытым.
- **«с» позже «по»:** кнопка сохранения недоступна.

## 6. Тесты
`tests/doctorreporttests.{h,cpp}` на подставном `DoctorReport`:
- уровни:
  - ✓ и «!» по целям;
  - `Unknown` без данных;
  - утечка без красной линии — `Unknown`;
- `html()`:
  - шапка с текущими настройками и «с какого числа»;
  - «–» без оксиметрии, без строки «Оксиметр»;
  - без личных данных нет имени и даты рождения;
  - текст экранируется;
  - таблица сравнения на месте;
- `chart()`:
  - размер картинки;
  - у ночи с данными в её колонке есть цвет столбика;
  - у ночи без данных колонка пустая;
  - в день смены настроек — серая линия;
- `writePdf()`: файл во временной папке начинается с `%PDF`; на 12 ночах и 11 строках таблицы —
  ровно одна страница (число объектов `/Type /Page`).

В `AnalysisIntegrationTests` (профиль во временной папке):
- `doctorReport()` за ночь с CPAP и оксиметром — часы только CPAP, `nights = 1`;
- период, урезанный по датам, — в строках сравнения только ночи внутри дат.

Глазами: отчёт профиля «Папа» за 03.09–02.10.2026 — одна страница, цифры совпадают с режимом
«Настройки» и стартовым экраном.

## 7. Вне рамок
- Увлажнение и другие параметры в «текущих настройках» — только то, что делит периоды
  (режим, давление, сброс давления).
- Отправка отчёта врачу (почта и т. п.).
- Несколько страниц с подробными графиками.
- Выбор, какие блоки печатать: все четыре всегда.
- Английская вёрстка как отдельная задача: строки переводимые, но проверяется русская
  страница.
