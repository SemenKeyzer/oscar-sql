## 1. Цель и контекст

Врачу нужно видеть, сколько ограничения потока было за ночь, в цифрах, которые OSCAR считает
сам, и Glasgow Index — открытую меру формы вдоха, известную по форумам и AirwayLab.

Владелец выбрал:
- Glasgow Index в **двух вариантах**: оригинал (числа совпадают с программой автора и AirwayLab)
  и адаптированный (пороги относительно силы вдоха, честнее для разных аппаратов, в том числе
  Prisma 20A отца);
- для времени ограничения — **обе цифры**: минуты участков и доля ограниченных вдохов;
- подробность — **итог + 9 признаков + графики** (по ходу ночи и по ночам);
- устройство — **подход A**: отдельный модуль внутри нашего анализа, результаты хранятся.

### Что уже есть
- `segmentBreaths` (`SleepLib/analysis/flow_analyzer.cpp:122`) — наши вдохи
  `Breath{start, inspEnd, end, pif, pef, vi, amplitude, fl}` в `FlowResult::breaths`;
  `flowLimitationScore` — оценка формы 0–1, порог `FlowParams::flThreshold = 0.5`.
- `flowLimitationSpans` (`flow_analyzer.cpp:238`) — участки `AN_FlowLimitation`: ≥3 ограниченных
  вдоха подряд (разрывы ≤500 мс) или ≥10 с; вдохи в апноэ/гипопноэ/неоценимом времени исключены.
- День: `DayResult::flSeconds` (сумма участков), `flSum`, `flBreaths`; таблица `analysis_daily`:
  `fl_time_s`, `fl_sum`, `n_fl_breaths`. Фигура «fl» в «Статистике» = Σ`flSeconds`/Σ`flowSeconds`.
- Порог частоты: ограничение потока оценивается только при потоке ≥10 Гц (`kFlHz`).
- Схема базы — версия 20; версия анализа `kAnalysisAlgoVersion = 2`.

## 2. Расчёт

### 2.1 Модуль `SleepLib/analysis/glasgow_index.{h,cpp}`
Чистый код без GUI и базы. Шапка файла: копирайт DaveSkvn, GPL-3.0-or-later, ссылка на репозиторий
и пометка «перенос FlowLimits.js, адаптация к OSCAR».

Признаки (порядок везде один): `Skew, Spike, FlatTop, TopHeavy, MultiPeak, NoPause, InspirRate,
MultiBreath, AmpVar`. Результат на сеанс:
```
struct GlasgowCounts { int breaths = 0; std::array<int, 9> flagged{}; };
// index() = Σ flagged[k]/breaths по 8 признакам, без TopHeavy; округление не делается
```
Плюс ряд значений по ходу ночи (см. 2.4).

### 2.2 Оригинал (`glasgowOriginal`)
Перенос функций `findMins`, `findInspirations`, `calcCycleBasedIndicators`, `inspirationAmplitude`,
`prepIndices` со всеми константами и особенностями:
- Вход — **сырые** отсчёты потока сеанса в л/мин (без нашего вычитания смещения и сглаживания),
  все куски `CPAP_FlowRate` сеанса по порядку, как `formDataArray` склеивает сигналы.
- Пороги в л/мин: вдох > 5, выдох-минимум < −10; Flat Top: дисперсия середины < 0,75;
  Multi-Peak: шаг 1 л/мин; Variable Amp: дисперсия 5 пиков > 4; Skew: левая доля < 45 % или
  > 55 %; Spike: время выше 90 % пика < 20 %; Top Heavy: > 40 %; Inspir Rate: > 20 вдохов/мин
  по 5 вдохам; No Pause: пауза до вдоха < 10 отсчётов; Multi-Breath: два вдоха на один выдох.
- Окна, заданные в отсчётах при 25 Гц, переводятся во время и обратно в отсчёты по реальной
  частоте `fs`: `n(fs) = round(n25 × fs / 25)`. Это `MIN_WINDOW` 25, минимальная длина вдоха 8,
  «короткий вдох» ≤12 (Skew → 50, top90 → 32), `EXTRAPOLATION_SAMPLES` 25, порог паузы 10.
  `AMP_WINDOW_LEN = 5` — число вдохов, не время. Inspir Rate: `5×60000 / (Δstart_ms)`.
- Особенности сохраняются как в JS: первые 5 вдохов и последний без Variable Amp, но в
  знаменателе; вдох без привязанного минимума не получает No Pause; `lastMax` в Multi-Peak
  обновляется только до первого спада; Top Heavy не входит в итог.
- При `fs` = 25 Гц результат совпадает с `FlowLimits.js` на тех же отсчётах.

### 2.3 Адаптированный (`glasgowAdapted`)
- Вдохи — наши (`FlowResult::breaths`, вдох `[start, inspEnd)`), на подготовленном потоке
  (смещение убрано). Вдохи, заблокированные для ограничения потока (апноэ, гипопноэ, неоценимое
  время), не проверяются и не входят в знаменатель.
- Не зависящие от силы потока признаки — как в оригинале, в секундах: Skew, Spike, Top Heavy
  (на отсчётах вдоха, «короткий вдох» ≤0,48 с), Inspir Rate (по 5 вдохам), No Pause (та же
  экстраполяция от минимума выдоха предыдущего вдоха на 1 с, пауза < 0,4 с).
- Пороги в л/мин заменены долями пика вдоха `P` (подобраны так, чтобы при `P` = 30 л/мин
  давать то же, что оригинал):
  - Flat Top: дисперсия середины / `P²` < 0,75/900;
  - Multi-Peak: шаг 0,033 × `P`;
  - Variable Amp: дисперсия 5 пиков / (средний пик)² > 4/900.
- Multi-Breath: вдох, перед которым у предыдущего вдоха не было настоящего выдоха — минимум
  потока выдоха выше −10 % медианы |PEF| соседних 5 вдохов.

### 2.4 График по ходу ночи
Для каждого варианта на каждом проверенном вдохе — индекс за последние 5 минут (вдохи, начавшиеся
в `(t−300 с, t]`): Σ по 8 признакам (без Top Heavy) доли отмеченных вдохов окна. Каналы
`AN_GlasgowIndex` и `AN_GlasgowAdapted` (новые номера в диапазоне `0x1A00–0x1A3F`), значение ×100,
метка времени — начало вдоха; хранятся как остальные события анализа (как `AN_FLScore`).

### 2.5 Время ограничения потока
Пороги и правила нашего анализа не меняются.
- **Минуты участков** — существующий `flSeconds` (сумма участков `AN_FlowLimitation`).
- **Самый длинный участок** — новый `flLongestSeconds` = максимум длины участка за ночь.
- **Доля ограниченных вдохов** — новый счётчик `flLimitedBreaths` = незаблокированные оценённые
  вдохи с `fl ≥ flThreshold`; доля = `flLimitedBreaths / flBreaths`.

### 2.6 Ночь и период
- Ночь из нескольких сеансов: счётчики суммируются (`breaths` и каждый `flagged[k]`), индекс
  считается из сумм; `flLimitedBreaths` суммируется; `flLongestSeconds` — максимум.
- Период (Статистика, сравнение настроек, отчёты): те же суммы по ночам; минуты — в среднем за
  ночь с оценённым ограничением (`Σ flSeconds / число таких ночей`); самый длинный — максимум.
- Порог частоты: оба индекса считаются только при потоке ≥10 Гц (как ограничение потока); иначе
  счётчики пустые, везде прочерк с подсказкой «поток записан реже 10 раз в секунду».

## 3. Хранение
- Описание анализа сеанса (JSON-штамп, `session_analysis.cpp`): ключи `gi` и `gia` (массив из 10
  чисел: вдохи и 9 счётчиков), `flx` (ограниченные вдохи), `fll` (самый длинный участок, с).
- `DayResult`: `GlasgowCounts glasgow, glasgowAdapted; int flLimitedBreaths; double flLongestSeconds`.
- Таблица `analysis_daily`, миграция **20 → 21** (`CURRENT_SCHEMA_VERSION = 21`), новые колонки:
  `fl_limited_breaths INTEGER`, `fl_longest_s REAL`, `gi_breaths INTEGER`, `gi_counts TEXT`,
  `gia_breaths INTEGER`, `gia_counts TEXT` (счётчики строкой «a,b,…» из 9 чисел; пусто — нет данных).
- `kAnalysisAlgoVersion` 2 → 3: при следующем запуске все ночи один раз пересчитываются (исходный
  поток не трогается, перезаписываются только строки анализа).
- Признаки отдельных вдохов не хранятся.

- **«Сводка»**: графики по ночам «Glasgow Index» (две линии) и «Минуты ограничения потока»

- **«Статистика»**, раздел анализа: строки «Минуты ограничения потока за ночь», «Самый длинный

- **Сводка для врача и PDF-отчёт**: строка ограничения потока дополняется минутами за ночь, долей
  вдохов и Glasgow Index (оригинал / адаптированный). Сводка остаётся на одной странице.

## 5. Тесты и проверка
- **Сверка с оригиналом.** Скрипт на Node.js (вне репозитория, в `reference/glasgow/`) загружает
  `FlowLimits.js`, прогоняет его на синтетических рядах при 25 Гц (парабола, плоская вершина,
  двойной пик, вдох без паузы, частое дыхание, переменная амплитуда, смесь) и печатает 9 долей и
  итог. Эти числа — эталон в тесте `GlasgowIndexTests`: совпадение до 0,01. Сами ряды строятся в
  тесте той же формулой (без чьих-либо данных).
- **Одна реальная ночь**: если в dev-профиле есть ResMed с потоком 25 Гц — сверка оригинала с
  `FlowLimits.js` на её BRP-файле (±0,02), только локально; данные не коммитятся.
- **Признаки по одному**: для каждого из 9 — вдох, который его даёт, и вдох, который не даёт.
- **Частота**: одинаковое дыхание при 25, 20 и 50 Гц даёт одинаковый индекс (±0,02).
- **Адаптированный**: при пике 30 л/мин совпадает с оригиналом (±0,05); при пике 15 л/мин
  оригинал отмечает Flat Top / Variable Amp, адаптированный — нет.
- **Пустые и редкие данные**: поток <10 Гц или пустой — счётчики пустые, без падений.
- **Время ограничения**: 3 ограниченных вдоха подряд — участок есть и идёт в минуты и в самый
  длинный; одиночный — только в долю вдохов; вдохи в апноэ не считаются.
- **Хранение**: миграция 20 → 21 на базе версии 20; запись/чтение строки ночи; ночь из двух сеансов
  складывается по вдохам; после смены версии анализа ночи пересчитываются.
- **Показ**: «Статистика» (новые строки, суммы за период), сравнение настроек, сводка для врача (одна
  страница), панель «Дня».
- **Приложение** — на данных отца (Prisma 20A), только `--datadir …/OSCAR20_Data_dev`: «День»,
  «Сводка», «Статистика», PDF-отчёт.
- Переводы: 0 незаконченных, `validate_ts.py` = 0.
